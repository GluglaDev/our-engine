# OUR Engine — Publishing checklist

## Before announcing the website

- [x] Create the public project repository.
- [x] Add the English project overview and public roadmap.
- [x] Add the static landing page, styles, scripts and SVG brand assets.
- [x] Add an automated GitHub Pages deployment workflow.
- [ ] Enable GitHub Pages with **Source: GitHub Actions** in repository Settings → Pages.
- [ ] Confirm the first deployment completes successfully.
- [ ] Open the published website on desktop and mobile.
- [ ] Check all navigation links and accessibility basics.
- [ ] Confirm the public/private project boundary and licensing terms.

## Before enabling sponsorships

- [ ] Create and verify the receiving accounts.
- [ ] Add only active, official sponsorship URLs to `config.js`.
- [ ] Review payment processor fees, identity requirements and tax obligations.
- [ ] Publish a clear explanation of how contributions may be used.
- [ ] Keep sponsorship optional; do not gate basic project information behind payment.

## Ongoing maintenance

- [ ] Keep the roadmap aligned with tested implementation.
- [ ] Describe prototype limitations honestly.
- [ ] Publish release notes for meaningful milestones.
- [ ] Review dependencies and their licenses before distributing binaries.
- [ ] Never commit passwords, access tokens, private keys or personal data.
